Ýeral Business — workspace shell

Every business screen sits in this shell: sidebar 248 (workspace switcher · Calendar · Bookings · Clients · Reviews · Settings · user block), top bar 64 (title, global search ⌘K, one primary action), content padded 32. First release = appointments only, so no Reports, Tables, Classes or Help in the sidebar; help is “Contact Ýeral” in the account menu. One Ýeral account (phone + code, the same as yeral.app) can belong to several workspaces with a different access level in each; a workspace = one business at one address. Addresses carry the workspace and no language: business.yeral.app/w/{slug}/… · log in at /login (B-Login) · setup at /setup/{step}.   • “Uses the app” (Specialist, on by default) replaces the old phone-only level. Off → bookable at once, never logs in, the owner and admins handle their requests; a phone number is still required — “They can start using the app later with this number.”
  • “Who answers requests?” (Settings → Booking rules: Owner and admins · Each specialist · Both, default Both) with a per-person override in the team drawer. The Bookings count = requests this person may answer; a Specialist under “Owner and admins” gets no count.
  • A direct URL to a hidden page redirects to Calendar with the toast “This section is closed to you”.
  • First release: appointments only — one booking type per business, so no Reports, Tables or Classes items.

  • Edited in Settings → Team → Permissions as this matrix: permission rows × Admin / Specialist columns. The owner changes cells; the Owner column is locked all-on.
  • “Own only” = only their own bookings, clients and earnings. Cells that can be “own” are a select None / Own only / All; the others are switches; Team is None / View only / Manage.

  • A Specialist always reads reviews about them; replying is the owner’s and admins’.
  • A Specialist with “Uses the app” off never logs in, so these permissions don’t apply to them.
  • No “Reports” row at the first release (no Reports section).
