# Ýeral Web — component map · design system v0.6 round 2 (20.10.2026)

**What this is.** The repo already has a design system in code: `@yeral/ui` (38 components, `packages/ui`) with Storybook 10 (`apps/storybook`, storybook.yeral.app), built from DS v0.3.1 (`screens/system/Main.dc.html`, `DS-Components.dc.html`, `DS-Booking.dc.html`). **Rules for Claude Code**
1. Before building a screen, look up every piece of it here. Status `exists` → use it. `extend` → add the listed variant/prop **and its stories** first. `new` → create it first: domain-free → `@yeral/ui` via `pnpm gen ui-component <name>`; domain → the FSD place in the row (`entities/*/ui`, `features/*/ui`, `widgets/*`), with stories in the same slice. `retired` / `remove` → don't build it (or delete it if it exists).
2. Build from the board, not from older screen markup: where screens drifted, the board holds the winner (drift lists below). Screens keep their layout and copy; components come from the boards.
3. Stories: one per variant and state on the board (default, hover, focus-visible, selected, disabled, loading, error, empty, long text, phone width), one per access level for permission-driven components, a `Playground`, `play` tests for keyboard + pointer, axe. The story file names its board and section.
4. No text inside components (labels/aria from props or i18n keys). Since v0.6 the boards are **English first** (`copy/EN-GLOSSARY.md`); each market adds its languages through the same keys (Turkmenistan: TK + RU; long-text rules on DS-Patterns 09). Values only from `tokens.css`. Domain-free components never import from entities.
5. Primitive ownership: if a domain component on DS-Business contains a primitive that DS-Patterns also draws (StatusBadge, BottomTabBar, NumberStepper, Checklist, CopyField, Pill, TimerPill, Stepper variants, SaveBar, WorkspaceSwitcher, AccountMenu…), the DS-Patterns primitive is the one to build; the domain component composes it.

# Part 1 — `@yeral/ui` (domain-free)

Board: `screens/system/DS-Patterns.dc.html` ("DS · Product components · v0.6", frame 1440 × 38 800 — content measured at ≈ 38 650 in a local headless browser with a fallback font). Every row below is drawn there with its states; the caption under each drawing repeats the Storybook title and names the version that won where screens drifted.
Domain components (calendar grid and blocks, request card, booking drawer, client card, review item, floor plan, class session, notification matrix, hours editor, permissions matrix, internal-status chip on a block…) are on `DS-Business.dc.html` and in its own map — this file covers only what belongs in `packages/ui`.

Rules that apply to every row: Radix primitive where one exists + `cva` variants + `cn()`; no text inside components (all copy, aria-labels and live-region messages come in as props — English is the source language since v0.6, every market adds its own); no fixed widths on anything with a label (Docs/LongText); values only from `tokens.css` v0.3.1 (see `token-audit.md` for the few proposed additions); scaffold with `pnpm gen ui-component <name>`; every story gets render + interaction + axe tests.

Storybook column: `exists — Title` = no change · `extend — Title: add …` = new variant / prop / story on an existing title · `new — Group/Title` = new component and stories · **retired** = drop the variant / story / example. Groups used: Actions, Display, Status, Inputs, Selection, Pickers, Navigation, Overlays, Data, Charts, Docs.

Rules from part B that every component above follows:
- **One booking per declined request.** Taking an offered time creates at most one booking (declined → Confirmed at once; unanswered → a new request, Confirmed at an instant business); the old row keeps a link to the new code and its chips disappear. Offered times bypass the phone-only restriction (**phone-only exception**).
- **Undo window = 5 minutes.** “Undo” exists for 5 minutes after a client cancel; it can fail (this time was given to another client · no spots left in the class · the booking has started · the request’s answer time ran out) → one shared message + “Pick another time”.
- **No silent specialist swap.** A move (and a booking) keeps the chosen specialist; the time grid shows only that person’s free times, or anyone’s with “Any specialist”. (Rule change — today the code reassigns to another free specialist.)
- **A move keeps the original.** Until the business answers, the booking stays at its time (client badge Confirmed + pending line; calendar original + ghost). Declined / unanswered → stays; accepted → moves. Only appointments move; tables and classes cancel + rebook. Moving follows the free-change window (2 hours before).
- **Current-slot start, no back-dated bookings.** Staff may start a booking or reservation at the current slot (`slotNow = floor(now / step) × step`: 11:20 → 11:15, tables 18:40 → 18:30); nothing earlier today is offered — recording a past visit is later.
- **Mobile numbers only** for SMS codes (+993 6… / 7…); a link page never shows or edits the full phone.

Rules that apply to every row:
- **Layers.** `entities/*/ui` = read-only views of one entity (no mutations, no routing); `features/*/ui` = one user action with its own model (mutation, optimistic update, toast); `widgets/*` = compositions placed on pages. Business app slices sit in `apps/business`, client-site slices in `apps/web`; shared entities (booking, venue, review, service, staff, account) keep one `model` and two `ui` flavours where the sites differ. Phone auth (`features/auth-by-phone`) is shared by both apps — one Ýeral account.
- **Copy.** No literal text in components: labels, statuses, aria-labels and live-region messages come from i18n keys. v0.6: the board is drawn English first (British English, sentence case — `EN-GLOSSARY.md`); each market adds its own languages through the same keys (Turkmenistan: Turkmen + Russian; RU runs about 30% longer — LongTextRU stories on BookingBlock, BookingRow, ResultRow, ServicePickRow).
- **Status tones + icons.** Only `--st-{pending|confirmed|completed|noshow|cancelled}-{bg,line,ink,dot}` from `tokens.css` v0.3.1, and one icon per system status (`statusesV2.system[].icon`). Status is never colour alone: icon + text in badges, icon on blocks, timer icon + number, strike for cancelled. What a level can’t use is **hidden, not disabled** (menu items, columns, tiles, buttons) — the only disabled controls are read-only views of data the person can see (Admin looking at Team / Permissions). Money renders only with revenue = all, or own money with revenue = own; components take `revenueScope: 'all' | 'own' | 'none'` and remove what is not allowed. Who may answer a request = workspace rule (`requestHandling`) ∧ per-person override; the owner always can.
- **Time.** All times are tabular numerals; positions on time grids are computed from minutes (`top = (start − from) × pxPerHour / 60 + 1`, `height = duration × pxPerHour / 60 − 2`).
- **Loading.** Skeletons copy the real geometry (`.sk` n-100, r6), appear after 300 ms, never a spinner for lists (States 08). Buttons show an inline spinner and keep their width.
- **Tests.** Every story gets render + interaction + axe tests; drag interactions also get a keyboard test; permission-driven components get one story per access level.

Storybook column: `exists — Title` = no change · `extend — Title: add …` = new story / variant on an existing title · `new — Group/Title` = new component · `remove — Title` = delete the v0.4 proposal.
