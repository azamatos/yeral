# Ýeral Web — component map · design system v0.4 (14.10.2026)

**What this is.** The repo already has a design system in code: `@yeral/ui` (38 components, `packages/ui`) with Storybook 10 (`apps/storybook`, storybook.yeral.app), built from DS v0.3.1 (`screens/system/Main.dc.html`, `DS-Components.dc.html`, `DS-Booking.dc.html`). Since then the full client site and the whole business workspace were designed. They introduced new components, variants, badges and patterns. DS v0.4 collects them, picks one canonical version of each, and maps every one to code. **The Storybook must grow with every new screen: no screen ships a component that has no stories.**

**Sources (read with this file)**
- `screens/system/DS-Patterns.dc.html` — "DS · Product components · v0.4": domain-free primitives and the new variants of existing `@yeral/ui` components → Part 1.
- `screens/system/DS-Business.dc.html` — "DS · Business patterns · v0.4": domain components (calendar, requests, clients, team, settings, reviews, notifications, analytics, billing, tables, classes, client-site cards) → Part 2.
- `tokens.css` v0.4 — v0.3.1 plus a few aliases for values the screens already used (Part 3, `token-audit.md`).
- Each drawing on the boards has a grey caption: `Name · package · Storybook: … · from: <screens>`. The caption and the row here say the same thing.

**Rules for Claude Code**
1. Before building a screen, look up every piece of it here. Status `exists` → use it. `extend` → add the listed variant/prop **and its stories** first. `new` → create it first: domain-free → `@yeral/ui` via `pnpm gen ui-component <name>`; domain → the FSD place in the row (`entities/*/ui`, `features/*/ui`, `widgets/*`), with stories in the same slice (Storybook already collects stories from those layers).
2. Build from the board, not from older screen markup: where screens drifted, the board holds the winner (drift lists below). Screens keep their layout and copy; components come from the boards.
3. Stories: one per variant and state on the board (default, hover, focus-visible, selected, disabled, loading, error, empty, long RU text, phone width), a `Playground`, `play` tests for keyboard + pointer, axe. The story file names its board and section.
4. No text inside components (labels/aria from props or i18n keys). Values only from `tokens.css`. Domain-free components never import from entities.
5. Primitive ownership: if a domain component on DS-Business contains a primitive that DS-Patterns also draws (NumberStepper, Checklist, CopyField, Pill, TimerPill, Stepper variants, SaveBar…), the DS-Patterns primitive is the one to build; the domain component composes it.
6. Copy is final TK draft (needs native review); new strings that exist only on the boards: "Goşuldy", "1 / 3 taýýar", "Bu döwür üçin maglumat ýok", "Başga döwri saýlaň", "Ýüklenmedi".

**Totals:** existing 38 → 34 to extend, 4 unchanged · new domain-free ≈ 52 · new domain ≈ 70.

**Suggested order** (matches the build order in `CLAUDE.md`)
1. Tokens v0.4 → `theme.css` + `tokens.test.ts`.
2. Extend the existing components the business shell needs first: SideNav (rail 72, switcher, user block, muted CountBadge), Button (danger-ghost, on-ink set), Input/Field (sizes 44/40/36, warning/success, counter), Chip, Table (sort, row states, bulk bar), Drawer/Modal (headers, footers, 560), StatusBadge (compact, clickable), Toast.
3. New primitives: Pill, TimerPill, DeltaPill, Callout, SaveBar, SettingsLayout/Group/Row, AppTopBar, InputGroup, CopyField, NumberStepper, TimeRangeField, Combobox, TagInput, Accordion, ProgressBar/Meter, Checklist, Timeline, StatTile, KeyValueList, AvatarStack, Kbd, PhotoManager, MapFrame, QrBlock; charts last (with Analytics).
4. Domain, in screen order: Business/Calendar (CalendarGrid, BookingBlock, ScheduleLayers, StaffColumnHeader, Toolbar) → Requests & Bookings → Clients → Onboarding & Settings → Services & Team → Reviews → Notifications → Analytics → Billing & Landing → Tables → Classes. Client-site domain components alongside the client pages.

# Part 1 — `@yeral/ui` (domain-free)

Board: `screens/system/DS-Patterns.dc.html` ("DS · Product components · v0.4", frame 1440 × 25 400). Every row below is drawn there with its states; the caption under each drawing repeats the Storybook title and names the version that won where screens drifted.
Domain components (calendar grid and blocks, request card, booking drawer, client card, review item, plan card, invoice row, floor plan, class session, notification matrix, hours editor…) are on `DS-Business.dc.html` and in its own map — this file covers only what belongs in `packages/ui`.

Rules that apply to every row: Radix primitive where one exists + `cva` variants + `cn()`; no text inside components (all copy, aria-labels and live-region messages come in as props); values only from `tokens.css` v0.3.1 (see `token-audit.md` (next to this file) for the few proposed additions); scaffold with `pnpm gen ui-component <name>`; every story gets render + interaction + axe tests.

Storybook column: `exists — Title` = no change · `extend — Title: add …` = new variant / prop / story on an existing title · `new — Group/Title` = new component and stories. Groups used: Actions, Display, Status, Inputs, Selection, Pickers, Navigation, Overlays, Data, Charts.

# Part 2 — domain components (FSD entities / features / widgets)

Board: `screens/system/DS-Business.dc.html` ("DS · Business patterns · v0.4", frame 1440 × 40 600, 13 numbered sections). Every row below is drawn there with its states; the grey caption under each drawing repeats the FSD place, the Storybook title and the screens it came from, and says which version won where screens drifted.
`@yeral/ui` primitives (Button, Chip, StatusBadge, Avatar, Drawer, Modal, Table, Menu, Switch …) are mapped in `components-ui.md`; patterns (Pill, Banner, StatTile, charts, CopyField, SettingsRow, SaveBar, NumberStepper, Uploader, Accordion …) are on `DS-Patterns.dc.html`. This file covers only what knows about bookings, staff, clients, money or venues — it lives in the app's FSD layers, never in `packages/ui`.

Rules that apply to every row:
- **Layers.** `entities/*/ui` = read-only views of one entity (no mutations, no routing); `features/*/ui` = one user action with its own model (mutation, optimistic update, toast); `widgets/*` = compositions placed on pages. Business app slices sit in `apps/business`, client-site slices in `apps/web`; shared entities (booking, venue, review, service, staff) keep one `model` and two `ui` flavours where the sites differ.
- **Copy.** No literal text in components: labels, statuses, aria-labels and live-region messages come from i18n keys (TK / RU / EN). RU runs about 30 % longer — every row has a `LongTextRU` story (drawn for BookingBlock, BookingRow, ResultRow, ServicePickRow).
- **Status tones.** Only `--st-{pending|confirmed|completed|noshow|cancelled}-{bg,line,ink,dot}` from `tokens.css` v0.3.1. Status is never colour alone: StatusBadge text, timer icon + number, strike for cancelled, icons for phone / alert note / completed.
- **Permissions.** Money (revenue, “Jemi”, planned revenue, plan prices) renders only with *Girdejini görmek*; components take `canSeeRevenue` and **remove** the column / tile (never blur or blank it).
- **Time.** All times are tabular numerals; positions on time grids are computed from minutes (`top = (start − from) × pxPerHour / 60 + 1`, `height = duration × pxPerHour / 60 − 2`).
- **Loading.** Skeletons copy the real geometry (`.sk` n-100, r6), appear after 300 ms, never a spinner for lists (States 08). Buttons show an inline spinner and keep their width.
- **Tests.** Every story gets render + interaction + axe tests; drag interactions also get a keyboard test.

Storybook column: `exists — Title` = no change · `extend — Title: add …` = new story / variant on an existing title · `new — Group/Title` = new component.
