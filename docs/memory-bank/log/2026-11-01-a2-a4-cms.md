# Slice 6 A2–A4: businesses, reported reviews, the team, the stack

- What's there: `/businesses` (the eight views, search), `/businesses/$id` (what the team checks, verify, send back, hide and show,
  close and reopen, a move checked), `/businesses/new`, `/reviews` (the 48-hour line, keep and remove), `/team` (add, a new setup
  link, turn off), the sidebar's waiting counts. `cms.Dockerfile`, both Compose files, the Caddy sites with the business app's
  policy, `deploy.sh`, CI's checks, `e2e/tests/admin.spec.ts`.
- Decided: the three pieces went as one PR, since only the e2e proves the screens against a real api and one PR is one CI round.
  `useErrorText` here says «This has already changed» for `invalid_status`, whose shared words speak of a booking.
- The e2e's account comes from `POST /v1/e2e/admin-invite` (`E2E_HOOKS`, off in production), the same call the server command makes.
  The e2e reads the setup's key and works out the authenticator's code itself.
- Not covered by the e2e: a reported review, as nothing in its stack reports one (stories and the api tests cover it); verifying,
  refused while the code shows on the screen.
