# 2026-10-30: HSTS and a Content Security Policy per site

From the 27.10 review (activeContext, Next steps 4): `yeral.caddy`'s `(yeral_site)` sent `nosniff`, a referrer policy
and `X-Frame-Options` only. One PR (`chore/hsts-csp`), deployed by hand later with the owner's go.

## What changed

- `infra/server/yeral/yeral.caddy`: `Strict-Transport-Security "max-age=31536000; includeSubDomains"` on every
  site; a `Content-Security-Policy` for `api.yeral.app` (strict; `/docs` apart) and `business.yeral.app`; none for
  `yeral.app`, whose app sends its own.
- `apps/client`: `src/app/entrypoint/csp.ts` (the policy and the nonce, with a test), `start.ts` (TanStack Start's
  request middleware: a nonce per request, the header on every HTML answer outside dev), `router.tsx` (`ssr.nonce`
  from `getGlobalStartContext()`), `vite.config.ts` (`start.entry`), `routeTree.gen.ts` regenerated.
- `infra/docker/Caddyfile` mirrors the production headers (a `yeral_site` snippet, the stack's api address); CI's
  «Docker stack» job asserts them: HSTS on each site, the api's and the business app's policies, and that the client
  page's nonce is on the header and on every `<script>` it writes.
- `www.yeral.app`'s redirect imports the snippet too (HSTS on the 301; the review's point).
- `deploy.sh` keeps the previous site file as `/srv/edge/sites-yeral.caddy.before-<commit>` and `-latest` (only when
  the file changed, so `-latest` is the one before the last change); the
  README has the rollback (`cp` back and `caddy reload`) and the post-deploy checklist ("Deploying Ýeral by hand"),
  and a "Security headers" section; `operations.md` points there.

## Decisions

- **HSTS without `preload`**: every `*.yeral.app` host is on TLS (`@`, `www`, `api`, `business`, `cms` on the server
  with Let's Encrypt; `storybook` proxied by Cloudflare: README, "DNS records"), so `includeSubDomains` costs nothing;
  the preload list can't be left quickly, so it waits.
- **The client site's `script-src`: a nonce per page, from the app.** TanStack Start writes inline scripts into every
  page (the hydration stream, `<script data-tsr-stream-part>`, React's streaming) that `'self'` would block and no
  hash could name (their content changes with the data). The version in use (`@tanstack/react-start` 1.169.3,
  `router-core` 1.171.38) supports a nonce cheaply: `createRouter({ ssr: { nonce } })` puts it on the hydration
  scripts, on `<Scripts />`'s module tags, on `HeadContent`'s assets (plus a `<meta property="csp-nonce">` the browser
  reads back) and into React's `renderToReadableStream({ nonce })`; a request middleware in a Start instance
  (`createStart({ requestMiddleware })`) hands the nonce to the router through `getGlobalStartContext()` and sets
  the header on the response. Three small files in `apps/client`, no new dependency. Checked locally on the built
  server (`node dist/node.mjs`): the header's nonce is on all four scripts of a page. So Caddy sets no policy for the
  apex: a fixed header can't carry a nonce, and `'unsafe-inline'` would have been the only other way.
- **The api's `/docs`** (Scalar's page: an inline `<style>`, an inline config `<script>`, the bundle from
  `cdn.jsdelivr.net`, and whatever that bundle loads: fonts, a proxy) isn't inventoried, so it gets only the
  directives that govern no loading (`frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src
  'none'`); everything else on the api gets `default-src 'none'`. Either the docs page's needs are inventoried later
  (self-hosting the bundle would make it `'self'`), or the page goes when the OpenAPI document is enough.
- `X-Frame-Options SAMEORIGIN` stays on the api too (the snippet); its `frame-ancestors 'none'` wins where both are
  read. No `report-uri` (nobody reads it; error tracking comes with P6). One snippet, the policies inline per site.
- `img-src` doesn't name `tiles.openfreemap.org`: MapLibre fetches tiles, sprites and glyphs (`connect-src`) and
  draws images from blobs; a `<img>` from that host doesn't exist. Nothing is allowed without a line below.

## Inventory (what each directive is for)

Built from the sources (`apps/client`, `apps/business`, `packages/ui`, `packages/sdk`, `packages/lib`) and the
built output (`apps/client/dist`, MapLibre 6.15's bundle, Scalar's renderer).

| Directive | Value | Needed by |
|---|---|---|
| `script-src` | `'self'` (+ `'nonce-…'` on the apex) | Vite's hashed modules under `/assets/`; the apex's inline scripts: `router-core/ssr/hydrationScripts.js` (`<script nonce>`), `react-router/ssr/renderRouterToStream.js` (React's `nonce`), `Scripts.js` (`getSsrBodyScriptParts(…, nonce)`); the business app's `index.html` has one module script, no inline one |
| `style-src` | `'self' 'unsafe-inline'` | the stylesheet (`styles.css`, Tailwind); `style={{…}}` in 13 files of the apps and `@yeral/ui`; `<style>{TOASTS}</style>` in `apps/business/src/widgets/workspace-shell/ui/workspace-shell.tsx`; MapLibre's own `<style>` and element styles |
| `img-src` | `'self' data: blob: https://api.yeral.app` | the brand icons from `/assets/`; uploaded photos and the demo photos from the api (`mediaBaseUrl` = `${site.urls.api}/media`, `apps/api/src/config.ts`; `/media/up/*`, `/media/demo/*`); MapLibre's `transparentPngUrl` (`data:image/png;base64,…`) and `img.src = URL.createObjectURL(blob)` for tiles and sprites. The QR (`@yeral/ui/qr-block`, `lean-qr`) is an inline `<svg>`; its PNG download is a `data:` `href` on a link, which no directive governs |
| `font-src` | `'self'` | Onest bundled from `@fontsource-variable/onest` (`packages/ui/src/styles/base.css`) |
| `connect-src` | `'self' https://api.yeral.app https://tiles.openfreemap.org` | `@yeral/sdk` (Hono RPC, `fetch`) and the events stream (`EventSource`, `packages/sdk/src/events.ts`, `GET /v1/events/stream`); OpenFreeMap's style (`OPENFREEMAP_STYLE`, `packages/ui/src/components/map-frame/map-frame.tsx`), glyphs, sprites and tiles, all through MapLibre's `fetch`; `'self'` for `/version.json`, route chunks and TanStack's own requests. The geocoder (Photon, ADR 0027) is called by the api, not the browser |
| `worker-src` | `'self'` | MapLibre's worker: MapFrame hands it the bundled file (`setWorkerUrl(import('maplibre-gl/dist/maplibre-gl-worker.mjs?url'))`, `map-frame.tsx` 137–141), same origin as the page, so `workerFactory` runs `new Worker(url, { type: 'module' })` on it directly; its blob wrapping is for a cross-origin URL only (`maplibre-gl-dev.mjs` 29186–29215). The review caught `blob:` here, written from that fallback path; no `blob:` |
| `frame-ancestors` | `'self'` (api: `'none'`) | the edge's `X-Frame-Options SAMEORIGIN`, kept |
| `base-uri`, `form-action` | `'self'` | nothing sets a `<base>` or posts a form elsewhere; the api: `'none'` outside `/docs` |
| `object-src` | `'none'` | no plugins |
| not allowed | `frame-src`, `media-src`, `manifest-src` | nothing embeds a frame, plays media or has a web app manifest. `maps.apple.com`, `google.com/maps`, `t.me`, `wa.me` are links the visitor follows (`packages/lib/src/links.ts`, `share-links.ts`), which no directive governs |

## Left

- Open the sites after the deploy with the console open (README, "Deploying Ýeral by hand" → the checklist): the
  inventory is read from code; a browser proves it.
- The api's `/docs` page: inventory Scalar's bundle (or self-host it) and give the page a real policy, or drop the page.
- The cms site, when its app joins `yeral.caddy`: a policy of its own from the same inventory (built on the business
  app's patterns, so likely the same one).
- `report-uri` / `report-to` with error tracking (P6), if the violations are worth reading then.
- The business policy is written three times (`yeral.caddy`, `infra/docker/Caddyfile` with the stack's api address,
  and the client's list in `csp.ts`); CI asserts the stack's copy and the client's, not that they agree. One source
  (the business image's own `static.Caddyfile` sending its policy with the api host baked in at build, as its other
  hosts are) would end the copying; left for when the policy next changes (10a: not before).
- `csp.ts` reads `OPENFREEMAP_STYLE` from `@yeral/ui/map-frame`, the component's module (MapLibre itself loads
  lazily inside it, so the server entry evaluates only the component graph); a leaf module for the tiles host in
  `@yeral/ui` would be cleaner, a `packages/ui` change this PR kept out.
