# Ýeral Web — design round 7 (export v0.7): from the owner's review of the live platform

You're updating the "Ýeral Web" canvas, last exported as **v0.6 round 3.4 (20.10.2026)**. Since then the repo has built
and launched all three apps from it: the client marketplace (yeral.app), the business workspace (business.yeral.app)
and the Ýeral admin tool. The owner and a partner went through the live platform and found that many problems aren't
bugs in the code: **the code follows the drawn pattern, and the pattern itself is wrong**. This round fixes those
patterns. Ýeral is moving from a demo to the MVP with real businesses.

The screenshots attached are from the live apps (file names are in brackets after each item).

## How to work

- **Foundations first (section A).** Draw the new components and rules on the DS boards (DS-Patterns, DS-Business,
  DS-Booking), then use them on every screen in B and C. Prefer one pattern used everywhere over a local fix per
  screen. Every component gets its states: rest, hover, focus-visible, active/open, disabled, error, loading, empty.
- **Real scale, not demo scale.** Draw lists with real-world numbers: 100 clients (five of them named "Jahan"),
  100 services in 15 groups, 20 staff, 300 bookings a week. A pattern that only works with 5 items is the problem
  we're fixing.
- **Simple over clever.** The owner's test: a basic user understands it without explanation. If a screen needs a
  caption to explain itself, redraw the screen.
- **Widths:** business at 1440 and 390, plus 1024 where the layout changes (icon rail). Client at 1440 and 390.
- **Copy in English.** The product is now built in English and each market adds its languages later (TK, RU). Don't
  draw new Turkmen copy. Fonts and components must still work for Turkmen Latin (Ä ä Ç ç Ň ň Ö ö Ş ş Ü ü Ý ý Ž ž)
  and Russian Cyrillic.
- **No "demo", "Example" or "this isn't a real business" anywhere.** Remove the Example badge and every demo notice
  from all boards.
- **Logo: skip.** A new logo is being drawn separately.
- Record every rule you set or change in a "Decisions log (round 7)" in `README.md` (client) and
  `business/README.md`, update `COMPONENTS.md`, and write `CHANGELOG.md` v0.7 with a **"To do in the repo"** list,
  one line per item below.

## A. Foundations (design system)

**A1. Numbers and the typeface.** The owner's main complaint: "the font we use for digits looks strange, the gap
between digits is too big — rethink it, let's change the font." Today Onest Variable is the only face and tabular
figures are on almost every number. Onest's tabular "1" sits in a full-width cell, so "+993 69 90 11 22",
"1,170 TMT", "10:15" and "13 bookings" all look loose. Draw a type specimen that compares, at 13/14/15/16/24/40 px:
(1) Onest as it is; (2) Onest for letters plus a companion face for digits only (for example Inter, Geist or IBM Plex
Sans); (3) a full replacement UI font with good Latin Extended and Cyrillic support. Show on each one: phone numbers,
prices, totals, the calendar's hour labels, time chips "10:15 10:30 10:45", stat tiles, a numeric table column, and
the 4-digit sign-in code. Pick one, update the tokens (`--font-sans`, plus a numeric font token if you keep a
companion), and write the rule for where tabular figures stay (only columns that must line up and the time grid).
[18.36.50, 18.40.04, 19.09.13]

**A2. Our own Select.** "I don't like all the select blocks: you just used the default select instead of making a
perfect one of our own." Today every select is the browser's native control (19 screens, plus every time picker with
48 options). Draw the Ýeral Select: the trigger at each control size; the open list as a raised popover with option
rows, a check on the selected one, hover/keyboard highlight and disabled options; group headers; a search field
inside the list when there are more than 8 options; a multi-select variant for filters (trigger reads "Services · 3");
a long list that opens scrolled to the current value (the time picker); an empty search result; on 390, the list as a
bottom sheet. Also draw the time field (HH:MM) for hours editors with it. [19.02.41, 18.27.43]

**A3. One control height per row.** A toolbar row today mixes 38 (segmented), 40 (select), 44 (tabs) and 48 (search
input) px controls, with different corner radii, so bottoms and tops don't line up. Set the sizes for Input (it has
only 48 today), Select, Segmented, Button and Chip so that each size matches across all of them, and say which size
toolbars use. [18.42.19, 18.53.25, 19.02.41]

**A4. Buttons that look like buttons.** The ghost and danger-ghost buttons have nothing at rest and a fill that
appears only on hover ("Remove from the team", "Turn off", "Home"). Several actions are bare violet or black text
("Book again", "Open the client's card", "Show all services", "Create a new client", "By phone number", "Clear").
Define: a tertiary button that's visible at rest; a quiet destructive button; a text link used only for navigation;
the icon button. Side padding is always larger than top and bottom. Then go through the actions listed above and say
which style each one takes. [18.26.34, 18.34.24, 19.14.16, 19.01.02]

**A5. One filter bar for every list.** "This filter is the worst thing in the world… we should create our own kind of
filtering that fits best and use it everywhere. What if there are 100 groups and services?" Draw one pattern: search ·
filter menus (single or multi, built on A2, with counts) · sort menu · active filters as removable chips · "Clear all"
· the result count. On 390: a "Filters" button with a count that opens a sheet. It must work for: business Calendar,
Bookings, Clients and Reviews; client Search results and the business page's Services. [19.09.58, 19.02.41, 19.23.14]

**A6. Tables: sorting and clickable rows.** Sortable column headers (none, ascending, descending). The whole row opens
the item, with a hover state. A single row action is an icon button, not a "…" menu. Rows stay on one line at 56 px:
tags get their own column with "+N" overflow and never wrap under the name. Long names truncate and never wrap to two
lines. [18.35.09, 18.36.48, 19.11.41]

**A7. Facts, status and breadcrumbs.** Secondary information joined with " · " wraps randomly ("Today 10:00–20:00 ·
Closed · opens tomorrow at 10:00" breaks in the middle; "since February 2026 · A friend recommended" sits next to the
tags). Define a pattern for status plus facts: a status pill ("Open until 20:00" / "Closed") with labelled facts on
their own lines. Breadcrumbs: links look like links, the current page is clearly the current one, chevron separators.
[18.46.02, 18.38.31, 18.43.21, 18.46.18]

**A8. Tags edited in place.** "Why does adding a tag work like a stupid form? Add the tag, save it, then save the
card." Draw tags edited in place: chips with ×, a "+ Add tag" chip that becomes a field, Enter saves straight away
(no form Save), suggestions from the business's existing tags, an undo toast after removing. Automatic tags (New,
Regular, Lapsed, Reported) look different and can't be removed. [19.11.16]

**A9. Info icon instead of hint lines.** Explanations under a field ("Only the team sees it · the booking status
doesn't change") become an ⓘ icon next to the label, with a popover. Draw the icon and the popover.

**A10. Callouts and toasts.** The "Bookings are confirmed at once" box puts a green success icon on a grey box, so it
reads like a toast, and the owner doesn't like green there. Set the tones for info and success callouts and toasts
(the primary violet is an option for info), and use them consistently. [18.43.05]

**A11. Focus ring.** On tabs the focus ring hugs the word with 2 px of air and touches the underline. Set the focus
ring's padding for tabs, chips and text links. [18.53.25]

## B. Business workspace

**B1. Hours with breaks** (business hours, own shift, special day). "Basic users won't understand the pattern." Today
each day is switch · day · two selects, with a second "Break 13:00–13:40 ×" row on another level. Draw the simplest
form a salon owner understands at a glance (for example a day as "09:00–13:00, 14:00–20:00", or a break that clearly
belongs to its day), on A2's time field. 1440 and 390. [18.27.43, 18.28.13, 19.06.51]

**B2. Calendar toolbar.** "Too many tab filters, and a select on top of them that's bigger than the tabs." Today one
row holds: Today · ‹ › · date · Day/Week · All staff/One specialist · a native staff select · a "2 requests" pill · a
"Show cancelled" checkbox · "+ New booking" · a "?" legend popover ("boolean, button, popover and badge in one row").
Rethink it: date navigation with a compact Today ("we can't give a whole filter to Today"); Day/Week; one people picker
instead of a segmented control plus a select; "Show cancelled" inside the filters; the request count as a badge;
New booking as the only primary; the colour legend somewhere quiet. 1440, 1024, 390. [19.01.46, 19.01.52, 19.02.06,
19.09.10]

**B3. Week view you can read.** Today the week for one person shows coloured blocks with no text at all, and the week
for all staff is a count matrix. Draw the one-person week with time, client and service in each block (and what a
15-minute booking shows), hover or focus to see more, and click to open; and the all-staff week. 1440 and 1024.
[18.31.23, 19.13.16]

**B4. Booking drawer.** "Call and Book again aren't in sync: Book again isn't even a button. 'Open the card' is a
link. Why is the visit count under the phone number?" Also: "Confirmed" and "By phone" don't read as a status ("what
does By phone even tell me?" It means the team entered the booking from a phone call). Draw: the status strip (the
status and the source as equal badges, with the source understandable); the internal status with A9's ⓘ instead of
the hint line; the client block as one card (name opens the card, phone with copy, visits as a fact, Call and Book
again as two equal buttons). 480 drawer and 390 sheet. [18.32.45, 19.07.57]

**B5. Clients list.** "Why are tags under the name? Why are rows so tall? Why statuses on a new line?" Use A5 and A6:
columns Name · Phone (copy icon beside the number) · Tags · Visits · Last visit · Total · Next booking, sortable by
Visits, Last visit, Total and Name; the whole row opens the card; the only row action is a "New booking" icon; delete
lives only inside the card; filters: segments with counts (All, Regular, New, Lapsed, Reported), tag, has an upcoming
booking. 390 list items. Empty and no-results states. [18.35.09, 18.36.48, 18.36.54, 19.09.58, 19.11.41]

**B6. Client card.** The head: the number with copy and Call; tags edited in place (A8); "Client since Feb 2026" and
"Source: a friend recommended" as labelled facts (A7), not a line after the tags. The alert note ("shown when
booking") as a note row with a warning icon. Today it's a full amber box with a violet pill inside, which the owner
finds "really strange; even the background colour doesn't fit the badge". History with "Show more". 1440 and 390.
[18.38.19, 18.38.31, 18.37.56]

**B7. New booking: finding the client and the services.** "Searching clients in a new booking is crazy. What if I
have 100 Jahans? The phone/name switch is unintuitive." Today: a "By phone number" text toggle, then matches as flat
rows under the field. Draw one client field as a combobox: type a name or digits (detected, no switch); a dropdown
of at most 8 results (name, phone, last visit, visits) with the match highlighted, telling the five Jahans apart;
"Frequent clients" before typing; "+ New client 'ja'" as the last row; the chosen client as a chip with Change.
Services: "Show all services" is a bare link today: make it a real control ("Jeren's services / All services") and
add a search for 100 services. [19.13.55, 19.14.16]

**B8. Bookings and requests.** Use A5 for the search and filters. On the Requests tab, the Answer cell stacks the
timer pill, ✓ and ✕ on three lines. Draw it on one line, or move the timer to its own column. [19.02.41, 19.15.27]

**B9. Team and permissions.** "How did we add this Management? I don't see a way to create such a role." Team groups
anyone who takes no bookings under "Management", and names wrap to two lines. Redraw the team table (groups that
make sense, or a "Takes bookings" column; names on one line) and the "Remove from the team" button (A4).
Permissions: "admin's description is on 3 rows; it's unreadable". Draw the matrix with symbols only (✓, —, a short
"Own" chip), equal columns, nuances as footnotes or ⓘ; on 390, one card per row. [19.04.32, 19.04.40, 19.09.40,
18.26.34]

**B10. Sign-in code by Telegram.** Sign-in codes now go to the user's Telegram (sent to the phone number's Telegram
account) instead of being shown on the screen. Draw the code step for the client site and the business app: "We sent
the code to your Telegram, +993 •• •• •• 10", resend with a timer, "No Telegram on this number?" help, wrong-code and
expired states. Remove the on-screen-code variant.

## C. Client site (yeral.app)

**C1. Home search: "the main pain".** "Looking for a place, service or time: see how strange, cheap and weird it
looks." Today one bordered card stacks "WHAT? / WHERE? / WHEN?" with bare text fields; the Where list overlaps the
button and gets cut; When is a native select. Redraw the hero search: What · Where · When with icons and real fields,
focus states, suggestions in a panel below the bar (What: categories, services, businesses; Where: Near me, cities,
districts; When: Today, Tomorrow, a date, a time of day, not a select), the search button. 1440 as a horizontal bar;
390 as a card that opens a full-screen search sheet. States: rest, focused, typing with suggestions, location
denied, nothing found. [19.45.50]

**C2. Business page.** "This is a business page: we need a wow effect." The gallery is one large photo plus four small
ones, and the icons are placed plainly. Draw a hero with a strong image composition (Fresha's gallery is a reference,
not something to copy) and the name, rating, category, open status, favourite and share built into it. On 390: a
cover that shrinks into the top bar as you scroll (Telegram's profile motion as a reference; describe the motion:
start and end states, what scales and what fades). [19.21.00]
- **Tabs as panels.** "Like YouTube: each tab is its own list. I don't want to scroll or go back." Today the tabs
  scroll to sections of one long page. Draw Services · Specialists · Reviews · About as separate panels, with no
  layout jump between them. The booking card stays. [19.19.46]
- **Breadcrumbs and the category.** The category in the breadcrumb isn't a link today. It will open the category
  page, which exists. Use A7. [18.43.21, 18.46.18]
- **Hours and status** with A7 instead of the run-on line. Show it once, not in both the header and the card.
  [18.46.02]
- **"Bookings are confirmed at once"** box with A10's tones. [18.43.05]

**C3. Services at scale.** The group chips (All · Hair · Nails · Facials · Massage) don't work for 15 groups and 100
services. Draw group navigation that scales (a chip rail with overflow, or a group index), and a search inside the
services. 1440 and 390. [19.23.14]

**C4. Booking steps.** "If I picked a service, I go straight to choosing the specialist. If I already picked the
specialist, I go to the services. I don't need that extra step." Today the steps are fixed (Services → Specialist →
Time → Confirmation), each needs Continue, and with a specialist picked a grey band "See all services" sits on top.
Draw both starts: from a service, picking it moves on to the specialist; from a specialist (picked on the business
page), the step shows only their services with the specialist as a done step ("Jeren · Change"). Adding a second
service happens from the summary ("+ Add a service") instead of making every pick a multi-select. 1440 and 390.
[19.20.47]
- **Summary card.** "This button composition is too perfect for this world" (sarcasm): Total, a full-width Continue,
  "Clear" as bold black text that reads like a heading, and "Pay at the place" all stacked with equal gaps. Redraw the
  hierarchy. [19.21.39]
- **Confirm step.** The business block is too small (a 56 px photo). Make it larger. The "number confirmed" check
  after the phone "looks weird and doesn't fit": give it a proper state.
- **Search results toolbar.** The day tabs and the sort select have different heights (A3).
